# HOW-TO 信息图：数据结构

## 1. 流程数据模型
建议以任务（Procedure）为根对象，步骤（Step）为核心记录：
- procedure_id：流程标识；
- goal：任务目标；
- audience：目标用户；
- prerequisites：前置条件；
- tools / materials：工具与材料；
- step_id：步骤编号；
- order：顺序；
- action：动作；
- object：操作对象；
- expected_result：预期结果；
- condition：判断条件；
- next_step：后续步骤；
- warning：风险或注意事项；
- evidence：完成检查依据；
- source：来源。

## 2. 关系类型
- 顺序：步骤 A 完成后进入 B；
- 分支：条件成立进入路径 A，否则进入路径 B；
- 并行：多个动作可以同时执行；
- 循环：未达到条件时重复某一步；
- 异常：失败、错误或中断后的处理路径；
- 依赖：某步骤必须等待另一任务完成。

## 3. 数据完整性
每个步骤应有明确动作和对象；分支必须有可判断条件；结束节点应定义成功状态。涉及安全、法律或专业操作时，必须保留原始来源和风险说明。

## 4. 推荐表达
先用结构化步骤表保存流程，再生成流程图或图形化步骤。不要只保留一张图而丢失条件、分支和操作说明。
